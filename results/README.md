# Per-seed raw results

These archives hold the per-seed raw results referenced in the paper *A Neurosymbolic
Benchmark for Temporal Knowledge-Graph Memory in Partially Observable Environments*.

## Contents

`roomkg-per-seed-results-neural.tar.gz`

| Tree | Runs |
|---|---|
| `training-results-simple-dqn/` | LSTM and Transformer baselines, training and held-out evaluation |
| `training-results-simple-dqn-temporal/` | the temporally informed neural controls (200 training runs) plus `_provenance/` launcher logs |

`roomkg-per-seed-results-symbolic.tar.gz`

| Tree | Runs |
|---|---|
| `training-results-symbolic/` | the TKG policy sweep: all 27 variants x 11 capacities x 5 seeds, on the training layout (`large-02`) and the held-out layout (`large-02-q`) |

These archives hold the TKG policy sweep and the neural runs, and nothing else. The KG
agent's per-seed runs are not included; see "A note on the KG agent" below. Earlier
cuts also carried runs from adjacent studies (a `large-03` layout the paper does not use,
a sweep over `remember_policy` values other than `all`, and meta-policies such as `borda`
and `memory_pressure`). Those share the directory layout and the same policy field names,
so aggregating by QA/exploration/eviction policy silently mixed them in. Aggregating what
is here now reproduces the reported figures directly, with no filtering.

Each run directory holds:

- `results.yaml` — per-seed scores
- `num_params.yaml` — model parameter count (neural runs only)
- `train.yaml` — the run configuration (agent, capacity, seed, policies, layout)

For the neural trees, a directory named `<timestamp>__test__large-02-q/` holds the
held-out evaluation of the run in `<timestamp>/`. For the symbolic tree the layout is a
field in `train.yaml` rather than a directory suffix.

## What is not included

Two per-run artifacts are omitted because they are diagnostic dumps rather than results,
and together they account for roughly 49 GB:

- `q_values.yaml` — full Q-value tables
- `states_q_values_actions_val_episode=*.yaml` — per-episode state, Q-value and action traces

Both are regenerated by re-running the training scripts; see the repository README.

## A note on the KG agent

The KG agent selects among equally ranked candidates with `random.choice` over an
unordered `rdflib.Graph` iteration, so its scores depend on Python's hash seed as well as
on the run seed. Fixing `PYTHONHASHSEED` makes a run reproducible; leaving it unset does
not. Its reported scores should therefore be read as one sample of that distribution
rather than as a value a re-run will reproduce exactly. The TKG sweep and the neural runs
are unaffected in this way.

For that reason the archives carry the aggregated KG series (in `../data/qa-accuracy-fig.json`)
but not a per-seed KG run tree: a per-seed dump would suggest a reproducibility the agent
does not have. Note that at the capacities where the agent never evicts, the remaining
nondeterminism is tie-breaking in `answer_question`, which picks uniformly among every
location ever stored for the queried object.

## Reproducing the aggregates

The aggregated series plotted in the paper live in `../data/`:

- `qa-accuracy-fig.json` — KG, TKG, LSTM and Transformer, train and test, all ten capacities, plus the 27-variant range
- `qa-accuracy-temporal-lstm.json`, `qa-accuracy-temporal-transformer.json` — the temporal controls

`plot-qa-accuracy.py` turns these into the QA-accuracy figure.
